# Перевірка реалізації

Дата: 22 вересня 2026. Версія: 0.2. Середовище: Windows, Python 3.12.1, OpenCV 4.14.0.94.

- **24 тести пройшли** в `parkflow/.venv`: 9 основних API, 2 геометрії та 13 перевірок камери з параметризованими сценаріями. Пропущених тестів немає.
- Встановлено базові залежності та OpenCV; Ultralytics/ваги моделі в цьому середовищі не встановлювалися.
- JavaScript пройшов `node --check`; Python-модулі пройшли `compileall`.
- Playwright + Microsoft Edge перевірили: завантаження схеми, бронювання, стан RESERVED в іншому браузері, відсутність чужих особистих даних, вхід адміністратора, в’їзд/виїзд, показ нарахування, другий поверх, EV-фільтр, рекомендацію, скасування та Swagger.
- Перевірено desktop 1440 px і mobile 390 px. Горизонтального переповнення сторінки на mobile не виявлено; скриншоти переглянуто.
- У фінальному браузерному прогоні не було JavaScript-винятків або помилок у console.

Окремий браузерний сценарій перевірив: відокремлені сторінки `/` і `/admin`, відсутність адміністративного JavaScript у водія, збереження RTSP без повернення пароля, запуск керованого процесу, JPEG-перегляд, позначення 4 кутів на canvas, збереження полігона, автоматичну зупинку при збереженні розмітки, повторний запуск, ручну зупинку, очищення кадру при виході та відновлення розмітки після повторного входу. Для цього використовувалося синтетичне відео з явним написом `TEST VIDEO`, а не фізична камера.

Нові серверні тести перевірили права адміністратора/Vision/гостя, відхилення HTTP і file URL, приховування секретів навіть у помилках валідації, збереження URL після перезапуску, перевірку полігонів, скидання геометрії при зміні джерела, заборону AI в демо, відсутні залежності, недоступність застарілих JPEG, реальне декодування локального відеофайла OpenCV в дочірньому процесі, ідемпотентний запуск, завершення процесу та видалення тимчасових кадрів.

AI-гілка обробки кадру, зіставлення детекцій із полігоном та запис batch перевірені з підставленою моделлю. Це перевірка логіки інтеграції, а не вимірювання точності YOLO. Базові сценарії бронювання, в’їзду/виїзду й EV-фільтра повторно пройшли браузерну перевірку після поділу сторінок.

Серверні тести включають конкурентне бронювання шістьма клієнтами, приватність даних, перевірки ролей та Origin, прострочення без затирання фізичної зайнятості, стабілізацію кадрів, відхилення запізнілих кадрів, атомарний rollback batch, ідемпотентні в’їзд/виїзд і фіксацію тарифу сесії.

Виявлену в браузері проблему Windows MIME для `.js` виправлено явною реєстрацією `text/javascript`; додано регресійну перевірку.

Попередження залежностей: Starlette попереджає про майбутню міграцію свого тестового клієнта з httpx та про deprecated alias AnyIO. Вони не спричинили падіння тестів.

**Не перевірено:** завантаження/інференс справжньої моделі YOLO, реальні RTSP-потоки, точність occupancy на польових даних, GPU-оточення та Docker-збірка. RTSP-адресу користувач ще не надав; фізичне підключення не виконувалось. Платежі, ANPR та керування шлагбаумом не реалізовані.
